# 边狱巴士汉化文本修改器（LimbusPatcher）

> 边狱巴士 / Limbus Company 零协汉化文本修改器：逐条对照零协原文编辑自定义译文，按楼层浏览 RPG 剧情，
> 查看人格 / 敌方 / 技能 / 被动 / 战中气泡图鉴，只写独立副本语言包，不修改原始汉化。
> Limbus Company LLC localization text patcher (PySide6, Windows) · v0.9.1 公测

面向《边狱巴士》零协汉化用户的绿色、可视化文本补丁管理工具。
搜索即可定位游戏文本，原文与自定义内容可视化对照；**只读取零协汉化，
仅写入独立的副本语言包**，不修改原始汉化文件，支持备份与恢复。
**没装零协也能用**：自动改用游戏自带的英文原文，浏览 / 搜索 / 对照 / 翻译照常。

## 下载与安装（v0.9.1 公测）

发布包在 GitHub Releases，两种任选其一：

| 包 | 体积 | 特点 |
| --- | --- | --- |
| `...-portable.zip`（单文件） | 约 48 MB | 一个 exe，双击即用；首次启动会先解包（约 1~2 秒） |
| `...-onedir.zip`（目录版） | 约 96 MB | 启动更快、杀软误报更少；解压后运行目录里的 exe |

解压到**任意可写目录**（别放 `Program Files`），双击 exe 即可；`data/` 会自动生成在 exe 旁。
每个包都附 `SHA256SUMS.txt`，校验：`certutil -hashfile <包名> SHA256`。

**没装零协汉化也能用**：程序会自动改用游戏自带的**英文原文**作为文本来源，
浏览 / 搜索 / 对照 / 翻译都照常（界面里是英文原文，你的译文正常保存与导出），
顶栏会显示「英文原文模式（未装零协）」并给出按钮——一键安装汉化：
<https://www.zeroasso.top/docs/install/autoinstall>。装好后回到程序点「重新检测」即可切回中文底本。
（「应用到游戏」需要零协汉化：副本语言包是从零协包镜像出来的。）

**怎么还原**：程序里「操作 ▾ → 还原为零协原包」；或直接删掉游戏目录下
`LimbusCompany_Data/Lang/LLC_zh-CN_custom` 并把 `Lang/config.json` 的 `lang` 改回 `LLC_zh-CN`。
程序每次应用前都会自动备份（`data/backups/`）。

**发布包内容**：程序 + 剧本**结构**数据（只存位置：相对路径 + 记录下标 + 字段路径）+ 说明文档。
**不含**任何游戏原文、零协译文或游戏素材；文本一律在运行时从你本机的语言文件读取。
第三方组件许可与免责声明见 `THIRD_PARTY_LICENSES.md`。

## 运行要求

- Windows 10/11（64 位）
- 已通过零协工具箱或手动方式安装零协汉化
  （游戏目录下存在 `LimbusCompany_Data/Lang/LLC_zh-CN`）
- 游戏基础语言设置为英文（零协汉化的既有要求）

## 快速开始

1. 双击 `边狱巴士汉化文本修改器.exe`（单文件免安装）。
2. 首次启动：点「自动扫描 Steam 库」，或「手动选择游戏目录」。
3. 等待文本索引建立（一次性的，之后秒开）。
4. 左侧分类浏览（对齐[边狱公司灰机 wiki](https://limbuscompany.huijiwiki.com) 术语）或顶部搜索（支持中文原文 / 自定义文本 / KeyID / 模糊匹配）。
5. 双击条目 → 右侧对照零协原文 → 输入自定义文本 → 保存。
6. 点「应用到游戏」→ 状态变为「已应用到游戏」。
7. 进入游戏：标题画面左下角语言按钮选择 `LLC_zh-CN_custom`（首次一次即可）。
8. 换电脑：整个文件夹拷走，重新定位游戏目录即可；也可以用「操作 ▾ → 导出方案包」把方案 + 剧本对应 + 备份打成一个 zip，在新机器上「导入方案包」恢复。

英文对照：编辑器可并排显示游戏英文原文（`Ctrl+E`），搜索范围可切到「英文」；详见下文「英语原文对照」。

几个顺手的细节：**关窗口会记住**上次的窗口大小、三栏宽度、分类/筛选/搜索词、停在哪一条，以及剧本模式停在哪一章哪一关（下次打开直接回到原处）；列表里 **Ctrl/Shift 多选**后右键可批量还原、批量收藏；列表搜索支持 KeyID（无 KeyID 的记录显示为「记录 #N」，同样可编辑）。

## 工作原理（重要）

产品方案中的 `changes.json` 是**本工具的补丁导出格式名**；游戏本身
（官方自定义翻译接口）并没有 `changes.json` 钩子。真实机制如下：

- 官方接口：语言包位于 `<游戏>/LimbusCompany_Data/Lang/<包名>/`，
  由 `Lang/config.json` 的 `lang` 字段决定启用哪个包，游戏按
  「文件名 + 条目 id」覆盖基础语言。
- 本工具把修改保存为**方案**（`data/profiles/default.json`，即便携补丁），
  应用时生成**合并副本包** `Lang/LLC_zh-CN_custom`（零协全文镜像 + 你的修改，
  只重写被修改的文件，UTF-8 BOM 编码），再把 `config.json.lang` 指向副本包。
  同步是**增量**的：没变化的文件按 (大小, mtime) 跳过（第二次起几乎瞬时），补丁文件按生成内容比对，只有真变了才落盘。
- 少数记录没有 KeyID（真实包约 1123 条文本叶子，多在人格剧情 `StoryData/P*.json`）：这些记录按下标定位，界面显示为「记录 #N」，搜索/编辑/应用与普通条目一致。
- 零协原包 `LLC_zh-CN` **一个字节都不会被写入**；游戏英文基线 `Localize/**` 同样只读（仅用于对照显示与英文搜索）。
- 零协更新后：工具自动重建索引，按条目给出「可继续使用 / 建议确认 / 无法定位」
  三档状态，修改永不自动删除。

## 人格图鉴（照游戏原版的信息层级）

顶部栏「人格图鉴」（或左侧「罪人」节点）打开，占据中间+右侧，导航栏保留：

1. **罪人**（12 位，带头像与人格/E.G.O 数量）
2. **人格 / E.G.O** 两个页签 → 卡片（头像 + 名字 + 协会与职位 + 技能/剧情/语音计数）
3. **人格页三页签**：技能 / 剧情 / 语音；**E.G.O 页两页签**：技能 / 语音
   - **技能 + 被动**：一张卡一个技能（形如 `1. 忍耐已经结束 · 3 级 · 2 硬币`），展开看各等级说明与硬币效果，点任一条就地修改；
     技能下面接一段 **被动能力**（◆ 名称 + 说明，人格来自 `Passives.json`、E.G.O 来自 `Passive_Ego.json`），点名称 / 说明同样就地改；
     基础 LCB 人格的技能在无后缀的 `Skills.json` 里，也一并认（否则这 12 个人格会显示「没有技能」）；
   - **剧情**：本地逐行（说话人 · 场景 · 正文），可逐行改，也可点「在剧本模式打开剧情」（本地渲染，标注未与 wiki 对照）；
   - **语音**：一格一条，**上面是类别（如「战斗胜利」「E.G.O觉醒」）、下面是台词**，点击弹出编辑（左原文 / 右自定义 / 英文对照）。
- 头部显示：第 N 人格（或基础/专用）、协会与职位、赛季与获取方式、英文名、获取条件（来自 `Personality_Get_Condition.json`）。
- 头部还有 **「改名称 ▾」**（改人格名称 / 罪人名 / 显示名 / 简介，写的是 `Personalities.json`、`Egos.json` 里的本体记录）与
  **「一键替换」**（范围限定在当前这个人格 / E.G.O 的全部文本）。
- 没有技能 / 剧情的原因：LCB 初始人格与活动特殊人格（愚人节、映画）在游戏本体里就没有独立剧情，
  少数特殊条目（如 `40501`）连技能表都没有；界面会直说「游戏本体没有…」，不是读取失败。
- 头像：`python scripts/extract_portraits.py` 从游戏 Unity 资源里抽（离线只读）。**实测只能抽到 133 个人格 + 1 个 E.G.O 的头像**（其余美术不在本地资源文件里），缺的自动退化为首字占位；也可把 PNG 放进 `data/portraits/identity/<人格id>.png`、`data/portraits/ego/<EGO id>.png` 覆盖。
- **风味小字（flavor）**：第 9 章起游戏给技能与被动写的小字（全包 技能等级 34 条 / 被动 181 条），
  图鉴里按小字（灰、斜体）显示在说明下面，点一下即可编辑；
- **多阶段敌人**：同一个敌人的多个形态（同一个 `Enemies-*.json`、同名同描述、**id 连续**，如 9-50 里恩
  `1347`/`1348`、魔王希斯克利夫 `8172`/`8173`，全包 28 组 / 63 个 id）在**敌方图鉴详情页顶部**有「形态 1 · 1347 /
  形态 2 · 1348」切换按钮，技能与被动跟着换；**按关卡查询**里也会把各形态一并列出（9-50 现在同时给出两段）。
  （只按名字分组会把「不识数的流氓 90004/99005/…」这类跨难度同名的 12 个 id 也算进来，所以要求 id 连续。）
- 技能里的**威力/硬币数值**暂不显示：这些不在本地化包里，需另取数据（灰机 wiki 或游戏数据表），且只读。

## 人格一览：按赛季 / 获取方式分组

左侧「罪人 → 全部人格 / 全部 E.G.O」（或中间列表上方的实体选择器选「全部人格」）时，
第二排会多出 **「分组」下拉**：

- **不分组**（默认）：一行一个人格，按罪人与序号排；
- **按赛季**：基础 → 第1赛季 … 第7赛季 →（瓦夜/活动/通行证单独成组）→ 未标注；
- **按获取方式**：常驻（基础）→ 赛季限定 → 通行证 → 活动赠送 → 瓦尔普吉斯之夜 → 未标注。

分组标题用强调色竖条 + 粗体，**括号里是该组数量**，「未标注」永远排最后（方便随手补数据）。
条数后面还会显示 **标注进度**（如「人格标注进度 184/198（93%）」），一眼看出还有多少没标。
数据来源 `limbus_patcher/data/season_map.json`（可用便携 `data/season_map.json` 覆盖，或走上面的豆包流程补全）。

## 人格 / E.G.O 体系（实体化浏览）

游戏文件里人格与 E.G.O 的归属、顺序都能直接拿到，工具据此把它们做成「实体」，技能 / 剧情 / 语音自动挂到名下：

| 内容 | 游戏里的出处 | 规则 |
| --- | --- | --- |
| 人格本体 | Personalities.json（187 条） | id = 1+罪人码+序号（10310）；desc 写「某某的第N人格」 |
| 人格技能 | Skills_Personality-XX.json | 技能 id = 人格 id × 100 + 技能号（1010501 → 人格 10105） |
| 人格剧情 | StoryData/P(人格id).json | 文件名即人格 id（P10710A → 10710，后缀为变体） |
| 人格语音 | PersonalityVoiceDlg/Voice_(罪人)_(变体)_(人格id).json | 187 个，后缀即人格 id |
| E.G.O 本体 | Egos.json（112 条） | id = 2+罪人码+序号；desc 区分基础 / 专用 |
| E.G.O 技能 | Skills_Ego*.json | 技能 id = EGO id × 100 + 技能号（覆盖 112/112） |
| 顺序 | StageChapterText.json / StoryTheater*.json | 章节编号（00/01/…/3.5/4.5）+ 放映厅条目 |

界面：

- 左侧「罪人」下每个人格 / E.G.O 有下拉选择器（`李箱 · 第1（LCB 罪人）` 形式，按罪人与游戏内序号排列），右边「内容」可切 **全部 / 本体 / 技能 / 剧情 / 语音**；
- 「人格一览（198）」「E.G.O 一览（112）」列出每个实体一行，行内显示 `技能 N · 剧情 N · 语音 N`；右键「查看该人格 / E.G.O 的全部内容」可直接跳进去；
- 「人格技能 / 人格剧情 / 人格语音」是跨罪人的聚合入口；列表行标注角色徽标（技能 / 剧情 / 语音）；
- **人格剧情不再混在「主线剧情」里**（20,343 条文本叶子单独归类）；`PC*` / `ES*` / `<章>D*` 等 201 个来历待确认的剧情文件暂归「其他剧情」。

## 补译文件（零协还没做的内容，例如新章节）

零协更新前，新章节（第十章等）在零协包里**根本不存在对应文件**，游戏会回退到英文。
「补译文件」让这类自己译好的文件也能随补丁进游戏：

```powershell
python scripts\install_supplement.py                 # 把 data/translate/out/zh/*.json 装成补译文件
python scripts\install_supplement.py --data-dir dist/data   # 装到 exe 同目录（打包版用）
python scripts\install_supplement.py --status          # 看清单与启用状态
python scripts\install_supplement.py --disable         # 全部停用
```

- 存放位置：`<数据目录>/supplement/<零协包内相对路径>`，例如 `supplement/StoryData/S1000B.json`；
- 程序里「操作 ▾ → 补译文件…」可以逐条启用/停用/移除/导入，顶栏有「补译 N/M」状态徽标；
- **应用到游戏**时：启用中的补译文件会写进副本包；停用或移除后，下次应用会把它从副本包删掉；
- 安全规则：只接受「可解析 + 有 dataList」的 JSON；**零协包里已有同名文件时以零协为准**，
  补译文件不会顶掉官方译文（应用时会给出提示）；
- 补译文件也能像零协文件一样在程序里逐条编辑（原文从 supplement/ 读，改动写进方案、叠加在补译文件之上）。

## 一键替换（批量查找替换）

入口：顶部「操作 ▾ → 一键替换…」（范围 = 当前列表筛选结果）、「工具 → 一键替换（全部文本）…」（全库），
以及人格图鉴详情页的「一键替换」（范围 = 当前人格 / E.G.O）。

- **先预览再应用**：表格逐条列出「位置 / 替换前 / 替换后」，可逐条取消勾选；
- **只写方案**：零协原文文件一个字节都不动，替换完仍要点「应用到游戏」才生效；
- **替换来源**：两者都替换（改过的条目在自定义文本上改，不会冲掉原有改动）/ 只替换零协原文 / 只替换自定义文本；
- **匹配方式**：区分大小写、正则表达式（支持 `\1` 反向引用）、整段完全匹配；
- 每条改动都进「修改历史」；顶部 **「撤销上次替换」** 可把这一次批量操作整体还原；
- 实现：`limbus_patcher/replace.py`（纯逻辑）+ `limbus_patcher/ui/replace_dialog.py`（界面）。
  正则里带 `|`、`?`、`*`、`[]`、`()` 这类「字面量片段不一定出现」的写法时，会自动退化成全库流式扫描
  （实测 17 万条 1～2 秒），保证不漏替换。

## 英语原文对照（只读参考）

编辑器支持 **零协中文原文 | 英语原文 | 自定义文本** 三栏并排：勾选按钮「英语原文」或按 `Ctrl+E` 显示，默认隐藏（状态记进会话）。

- 数据来源：游戏本体的英文基线 `LimbusCompany_Data/Assets/Resources_moved/Localize/en/`（`<目录>/EN_<文件名>.json`）。**只读**——工具绝不写入该目录，也不写零协包。
- 覆盖实测：零协 170,524 条文本叶子里 **163,876 条（96%）** 能取到英文；取不到时分两种中文提示：「英文无此字段」（英文记录缺 `name/desc` 等）与「该文件没有英文基线」。
- 匹配规则（宁缺勿错）：英文文件里只要有 KeyID 就**只按 KeyID** 对应；只有英文文件整份都没有 KeyID 时才按记录下标对应，绝不拿别的台词顶替。
- 搜索：搜索框右侧「范围」可切 **原文 / 英文 / 自定义 / 全部**——用英文关键词反查条目、或搜自己写过的自定义文本（以前搜不到）。命中英文时列表行会标「英文命中」。
- 检查状态：「操作 ▾ → 英文基线状态…」显示基线目录、文件数、对照覆盖率与可选语言目录（游戏另带 `jp` / `kr`）。
- 换语言：配置项 `baseline_lang`（默认 `en`）指向 `Localize/<lang>`；改动后索引会自动重建。

## 剧本模式（剧情关卡视图，集成在中间列表）

- 数据来源：灰机 wiki 剧情脚本页（`scripts/crawl_wiki_story.py` 爬取 534 页）+ 文本匹配对应本地零协 `StoryData`（`scripts/_match.py`），再按行对齐为剧本行 items（`scripts/_align.py`，说话人按语音图切分 + 本地 teller，场景行取 wiki ### 标题与本地 place 变化，保留 ruby 注音），产出 `limbus_patcher/data/story_stages.json`。
- 入口：顶部栏「剧本模式」按钮（默认当前章节/第一章），或「主线剧情」中打开任意剧情条目后点右侧「剧本模式」
- 剧本模式内可**切换章节与关卡**（顶栏两个下拉）；**未对齐行单击可手动建立与零协记录的对应**（建立后即可编辑），右键可标记跳过；手动结果存 `data/cache/story_overrides.json` 并合成到 `data/cache/story_stages.json`
- 使用：在「主线剧情」打开任意剧情条目 → 点右侧「剧本模式」按钮 → **中间列表切换为该关卡的剧本**：说话人左侧（头衔小字在上）、文本右侧长条、场景分隔行、ruby 注音小字显示在正文上方；**单击某行 → 右侧照常编辑该条**；顶栏「⟵ 切回条目模式」返回。不再使用独立弹窗。
- 覆盖：**序章 + 第 1~9 章（主线）** 的剧本行已逐行对齐；本地包与 wiki 措辞不一致的台词显示为灰色只读（当前约 178 行，多为零协与 wiki 的用词差异，更新汉化后可重新匹配）。间章 / 活动 / 集中战斗 / 播报员暂不纳入剧本行。
- 更新数据：一条命令即可重跑「解析 → 页面匹配 → 按行对齐 → 写回包内数据」：`python scripts/rematch_all.py`（可选 `--skip-crawl` 跳过重新解析；零协汉化更新后建议完整跑一次，然后重新打包）。


### 剧本模式快捷操作（v0.2）

| 操作 | 说明 |
| --- | --- |
| ↑ / ↓ | 在当前关卡剧本中移动焦点行（高亮显示） |
| Enter | 对焦点行执行：未对齐 → 打开「建立对应」；已对齐 → 载入右侧编辑器 |

| 右键未对齐行 | 「从该行起批量对应…」/「自动建议对应（本关 N 行）」/「删除该行」/「删除本关全部未对应行（N 行）」 |

- **自动建议对应**：对未对应行按文本相似度自动配到「未被占用」的零协记录（默认阈值 85%，只建议几乎一字不差的行），弹窗逐条确认后批量写入；「操作 ▾ → 自动建议剧本对应…」可对整个主线一次性处理。
- **大关卡分批渲染**：一屏只建 120 行控件，行尾给「▼ 继续载入剩余 N 行」，滚到底 / 按 ↓ 越过末尾 / 点提示行继续补齐。

### RPG 关卡的剧情分支（第十章 10-4 为首个用例）

第十章第 4 关（`10-04`，西西弗百货）是 **RPG 关卡**：它的剧情不在 `StoryData` 的过场文件里，
而是散在 `RPGSystem/` 的楼层对话 / 选项 / 旁白里，和过场交替出现；本地化文件**没有**触发器数据，
所以「玩家游玩顺序」靠一张编排表确定：

- **编排表**：`limbus_patcher/data/story_rpg_plan.json` —— 每个关卡按顺序列出 `branches`
  （每段 = 若干 `parts`：文件 + `dataList` 记录区间），并附 **顺序依据（evidence）** 与
  **把握度（confidence，high/medium/low）**。改顺序只改这张表。
- **重建**：`python scripts/build_story_rpg.py --stage 10-04`（幂等；会同时刷新开发态
  `data/wiki_story/` 与打包版 `dist/data/cache/` 两份运行时副本，否则它们会盖过包内数据）。
- **文本来源**：一律零协包（`Lang/LLC_zh-CN`）→ `data/supplement` → 英文基线（仅兜底并告警）。
  本关 3809 行 100% 来自零协原文（此前是早期机翻稿，一致率仅 ~5%）。
- **按楼层分段**：剧本模式的关卡下拉里，`10-04` 下面直接列出**楼层**（`        └ 02 1F·西西弗百货`、
  `└ 03 2F·奢侈品馆` … `└ 09 终盘`），顺序就是游玩顺序（1F→2F→3F→4F→B1F→B2F→回3F→终盘），
  点某一层只看该层剧情；选关卡本身=看全关。段内再用 `◆ 过场·克罗默之姐` / `◆ 探索·扶梯厅`
  这类小节标出这一层里过场与探索的交替位置。分支进度会随会话一起记住。
- **剧本骨架**：每个 RPG 段开头插一条不可编辑的 `【任务】Q1011 探索周围：…`，
  让读者看得到 RPG 的推进线（任务来自 `rpg-loc-quest-*.json`；空描述 / `0901追加` / 「未使用」的任务已过滤）。
- **可编辑**：RPG 行的文本叶子是 `texts[i].text`（记录没有 KeyID），剧本模式点击会按
  `record + text_index` 精确定位到编辑器；选项等单文本记录走 `text` 字段。
- **体检与对照**：
  `python scripts/verify_story_rpg.py --stage 10-04`（来源 / 覆盖 / 顺序 / 结构四项硬检查，
  外加 key 前缀与楼层、说话人的提示级检查）；
  `python scripts/export_story_rpg.py --stage 10-04` 出 `data/translate/out/第十章-10-04剧情-中英对照.md/.csv`。
- **回归**：`pytest tests/test_story_rpg.py`（生成器 / 定位 / 出厂数据 / 分支面板 / 编排表一致性）。

> `04 3F·品牌世家` 里的 `◆ 过场·默尔索妈妈（位置待确认）`（S1010B）置信为 low —— 本地文件找不到
> 它的楼层锚点，只能按上下文放；其余位置的依据都写在编排表的 `evidence` 里，改 `parts` 重跑即可。

## 分类体系（对齐灰机 wiki 术语）

```text
角色与战斗  罪人(12名，每名下属 人格 / E.G.O) · 人格剧情 · 技能 · 战斗效果 · 异想体 · 敌方单位 · 战斗对话 · 罪人资料

系统与界面  界面文本 · 系统提示 · 教程 · 道具与货币
其他        歌词、特效设置等
```

说明：
- **罪人树**：左侧「角色与战斗」下先按 12 名罪人（李箱/浮士德/堂吉诃德/良秀/默尔索/鸿璐/希斯克里夫/以实玛利/罗佳/辛克莱/奥提斯/格里高尔）分组，每名罪人下再分**人格**与 **E.G.O** 两级浏览（例如 良秀 → 人格 → 蜘蛛巢之刃等）；由人格/E.G.O 条目 id 自动推导，无需维护数据。
- **间章剧情（3.5/4.5/5.5/6.5/7.5/7.5续/8.5/8.5EX）归入「主线剧情」分类**，选择「主线剧情 + 章节=间章4.5」即可查到对应剧情；「间章与活动」保留瓦夜、愚人节、周年等非主线活动。
- **人格剧情**（剧场/镜世界人格故事）从「人格」分类独立出来。
- 列表按文本**去重显示**（相同文本合并一行并标注「重复 N 处」，保留已修改/待确认/失效的那条优先），剧情里角色名、称号、地点等重复文本不再刷屏；如需逐条编辑，按分类/关卡筛选即可分开。

列表副标题按 wiki 习惯给出章节/模式提示（如「第7章 第3部分」「瓦夜4」「镜牢3」
「折射轨道1号线」「间章 7.5」）；左侧顶部另有「全部文本 / 我的收藏 / 最近修改 / 待确认」
快捷入口，「待确认」直达汉化更新后需核对的条目。

## 分类数据维护（手工）

分类体系由 `limbus_patcher/data/` 下的三个 JSON 文件驱动，可直接手工编辑：

| 文件 | 内容 | 生效方式 |
| --- | --- | --- |
| `category_rules.json` | 文件名→分类的规则（有序正则）、分类中文名、分组、间章提示 | 重启程序 + 「重建文本索引」 |
| `season_map.json` | 人格/E.G.O id → {season, acq}（0=基础/常驻，N=第N赛季；acq: base/seasonal/event/pass/walpurgis）——已由豆包对灰机 wiki 全量核对补全（298 条，标注进度 100%） | 改完自动重建索引 |
| `enemy_map.json` | 敌方 id → {group, label}（group: abnormality/faction/unit） | 「重建文本索引」 |
| `entity_exclude.json` | 不进图鉴的实体 id（现有：愚人节整活人格 400025~400036） | 「重建文本索引」 |

- 覆盖方式（便携目录优先于包内）：分类规则放 `<exe 目录>/data/category_rules.json`；
  赛季/敌方映射放 `<exe 目录>/data/cache/season_map.json`（`import_season_answers.py --deploy <exe 目录>` 会自动铺过去）。
- 校验与缺失清单：`python scripts/check_maps.py --game-dir "<游戏目录>"`，会列出「尚未标注」的人格/E.G.O/敌方 id，直接照着补 JSON 即可。
- 赛季 / 获取方式已由豆包对着灰机 wiki 核对补全（见下节）；以后要改直接手工编辑 `season_map.json` 即可，改完**索引会自动重建**（赛季列进指纹）。
- 不想在图鉴里看到某些人格/E.G.O（例如愚人节整活人格：游戏本体没剧情没语音、也没有赛季归属），
  把它们写进 `entity_exclude.json` 的 `identities` / `egos` 即可：这些人格不再出现在图鉴、人格一览、
  赛季统计里，**但它们的文本条目照旧留在索引里**（能搜、能改名、能替换），不会丢内容。
  该文件的内容也计入索引指纹——改完下次启动自动重建索引，不用升 schema。

### 赛季 / 获取方式：豆包核对补全（老规矩）

```powershell
python scripts\export_season_tasks.py      # 198 人格 + 112 E.G.O → data/seasons/paste/01_人格.txt …
python scripts\send_season_tasks.py         # 把「下一片」复制进剪贴板 + 唤起豆包 + 选中文件
python scripts\send_season_tasks.py --status  # 只看 13 片贴到第几片了
python scripts\import_season_answers.py     # 汇总 data/seasons/ans/*.json → limbus_patcher/data/season_map.json
python scripts\import_season_answers.py --dry-run        # 只看会补/会改哪些，不写文件
python scripts\import_season_answers.py --apply-changes  # 连「与现有标注不同」的答案也接受（写进变更报告）
```

- 每片 txt **自带提示词**（整文件粘给豆包即可），回包 JSON 存成 `data/seasons/ans/<同名>.json`；
- 默认**只补缺失**：现有标注（来自 wiki.gg）不会被覆盖，改动要显式加 `--apply-changes`；
- 跑完在程序里「工具 → 重建文本索引」，人格一览的「按赛季 / 按获取方式分组」即用新数据；
- 变更明细写在 `data/seasons/变更报告.md`（补全 / 改动 / 未识别 id）。
- `scripts/fetch_season_map.py` 是参考用的自动生成脚本（数据来自公开 wiki API，会**覆盖**上述两个 map 文件，手工维护时请勿随意运行）。
- 章节→关卡的分组由文件名推导（`limbus_patcher/story.py`），无需维护数据。

## 出问题时看哪里（崩溃 / 行为诡异）

打包成 windowed exe 后没有控制台，所以程序自己往 `<exe 目录>/data/` 写日志：

| 文件 | 内容 |
| --- | --- |
| `crash.log` | 未处理异常、后台线程异常（索引/部署线程）、被忽略的异常（`__del__` 等） |
| `crash_native.log` | 原生崩溃（访问越界 / 栈溢出 / abort）时的 Python 栈（faulthandler） |
| `qt_messages.log` | Qt 自己的警告与致命信息（如字体尺寸非法） |
| `backups/*.zip` | 「应用到游戏」「清空」前的自动备份 |

单个日志超过 2 MB 会自动清空重来。

### 改了「索引内容」的逻辑，记得 +1

`limbus_patcher/index.py` 里的 **`BUILDER_VERSION`** 是索引**内容语义**版本：只要改动
实体/角色推导、分类归属、条目归属这类逻辑（例如新增敌方实体支持），就要把它 +1，
否则会出现「新程序 + 旧索引」——数据指纹看不出来，界面只会静默变空或行为诡异。
+1 之后程序启动会自动整库重建（约 13 秒）。

> 关于「每次启动都在重建索引」：`manifest_matches()` 除了比对零协包，还会逐条比对英文基线文件。
> 零协包里有若干 2 字节空壳文件（`AbEvents-a1c5p1.json` 之类，内容是 `{}`）会被结构检查跳过，
> 以前它们不会写进 manifest 的 `baseline_files`，于是每次启动都被判成「新出现了英文基线文件」→
> **每次启动全量重建（实测 13.8 秒）**。现在由 `_fill_missing_baseline()` 补齐记录，
> 启动时只做一次 manifest 比对（约 0.3 秒），只有零协包 / 基线 / 规则真的变了才重建。
