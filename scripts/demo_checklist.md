# 模拟验收清单（无游戏环境）

> 用 `tests/fixtures` 的模拟零协安装完成全流程验收，或参照最后一节在真实游戏机器上验证。

## A. 模拟环境验收（已自动化为 scripts/demo.py）

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\demo.py
```

预期：全部步骤输出 ✔。步骤覆盖：首次引导 → 环境检测 → 索引 → 搜索 → 编辑保存 →
应用（原包哈希不变 / 副本包 BOM / config.json 切换）→ 汉化更新兼容提醒 → 清空 → 停用 → 备份恢复。

## B. 手动 UI 冒烟（本机，无游戏）

```powershell
.\.venv\Scripts\python.exe main.py
```

1. 首次启动应显示引导卡片，而不是空白窗口。
2. 点「手动选择游戏目录」，选择 `tests\fixtures\game`。
3. 等待索引完成（状态栏显示「索引就绪：5 个文件」）。
4. 左侧出现分组导航（角色与战斗 / 剧情与模式 / 系统与界面 / 其他，分类名对齐灰机 wiki 术语：
   人格、E.G.O、技能、战斗效果、异想体、敌方单位、战斗对话、罪人、主线剧情、间章与活动、
   折射轨道、镜牢、界面文本、系统提示、教程、道具与货币）。点「战斗效果」分组下的分类，中间列表出现条目。
5. 搜索「群体攻击」，双击命中条目；右侧显示零协原文（只读）。
6. 输入自定义文本 → 保存 → 顶部状态变为「已保存到方案」。
7. 点「应用到游戏」→ 顶部状态「已应用到游戏」。
8. 打开 `tests\fixtures\game\LimbusCompany_Data\Lang`：
   - `LLC_zh-CN` 原包内容与修改前完全一致；
   - 新增 `LLC_zh-CN_custom` 副本包；
   - `config.json` 的 `lang` 指向 `LLC_zh-CN_custom`。
9. 「显示差异」按钮应高亮差异行；「历史」按钮可回退版本。
10. 异常演练：
    - 把 `config.json` 改成乱码 → 顶部环境状态变红，提示可执行下一步；
    - 删除 `LLC_zh-CN` 中某文件后「重新检测环境」→ 索引重建且条目不丢失；
    - 搜索无结果 → 提示「清除筛选 / 放宽条件」思路（计数标签与空列表）；
    - 把 `data\profiles\default.json` 改成乱码 → 重启工具 → 空方案 + 可通过「备份管理」恢复。

## C. 真实游戏机器验收（十秒流程，对应产品方案第 11 节）

前置：已通过零协工具箱安装零协汉化（`LimbusCompany_Data/Lang/LLC_zh-CN`），
游戏基础语言为英文。

1. 启动修改器（首次自动备份）。
2. 首次运行：点「自动扫描 Steam 库」或手动选择游戏目录；等待索引完成。
3. 搜索目标文本（如技能名「群体攻击」）→ 双击 → 对照零协原文。
4. 输入自定义文本 → 保存（顶部：已保存到方案）。
5. 点「应用到游戏」（顶部：已应用到游戏）。
6. 启动《边狱巴士》，在标题画面左下角语言按钮确认选中 `LLC_zh-CN_custom`
   （首次需手动选一次，之后游戏会记住）。
7. 进入游戏验证修改生效。
8. 更新零协汉化后：重新打开修改器 → 自动重建索引 → 顶部出现「N 条文本需要确认」；
   逐条核对后重新「应用到游戏」即可（修改永不自动删除）。
9. 想还原：单条用「还原为原文」；全部用「清空全部修改」；临时停用用「停用修改」。

## D. 安全保证抽查

- 全程不修改 `LLC_zh-CN`：应用前后对该目录做哈希对比（demo.py 已断言）。
- 所有 JSON 由标准库序列化生成并回读校验，不存在字符串拼接。
- 写入顺序：方案先落盘 → 副本包逐文件原子替换 → config.json 最后切换，
  任何一步失败不影响游戏当前可用的语言包。
