# 新章节翻译方案（第十章为首个用例）

> 目标：把新出的章节文本从**英文基线**译成中文，**专有名词一律以零协既有译法为准**，
> **留中英对照**，翻译工作**外包给豆包**（分片 → 回包 → 机器校验 → 合并），
> 整套流程参数化，**下一章直接复用**。

本方案配套脚本：`scripts/build_glossary.py`（已实现）、`scripts/export_translate_tasks.py`、
`scripts/send_translate_tasks.py`、`scripts/import_translate_answers.py`（待实现，接口见第 6 节）。

## 2. 专有名词保真：四层机制（全部机械可查，不靠人记）

### L1 术语表（已实现，实测 1 833 条）
`scripts/build_glossary.py` 把英文基线与零协包**按 `id` 配对**，取「英文名 ↔ 零协中文名」：

| 来源表 | 类别 | 条数 |
| --- | --- | --- |
| Passives / Skills / Enemies / Items | 被动 / 技能 / 敌方 / 道具 | 598 / 551 / 492 / 106 |
| BattleKeywords / Bufs / SkillTag / UnitKeyword | 关键词 · 状态 · 技能标签 | 全部 |
| Personalities / Egos / Abilities / StoryTheater / StageChapterText | 人格 · E.G.O · 能力 · 放映厅 · 章节名 | 全部 |
| **合计** | | **1 833 条**（冲突 16 处已跳过并记录） |

- 生成物：`data/translate/glossary.json`（机器用）、`data/translate/术语表.md`（人看，1.7 千行）
- **硬规则**：译文里出现的每个术语，必须与表里的中文完全一致（大小写、标点、全半角都按表）。
  导出时把该片命中的术语做成子表塞进提示词；导入时逐条自动校验，违规直接打回。

### L2 说话人对照（已实现，实测 392 条）
剧情记录的 `model`（韩文立绘 id）在两边一致 → 用零协已译章节反查「model → 中文叫法」。
生成物：`data/translate/说话人对照.md`。**新章节同一个 model 直沿用中文名，禁止另起叫法**；
`teller` / `title` 里的 `???` 一律照零协写法译成 `？？？`。

### L3 新词候选 + 旧章节证据（已实现，实测 334 个候选，其中 228 个带证据）
新章节里出现、术语表未覆盖的大写词组/引号词，逐个回查第 1~9 章找**英文原句 + 零协中文句**：

| 候选 | 次数 | 旧章节证据（英文 → 零协） |
| --- | --- | --- |
| Grand Magasin Sisyphe | 17 | Raw ingredients for Canned Experience… → 罐头的原料只会在**西西弗百货**被处理… |
| Golden Bough | 9 | …collecting more Golden Boughs → 随着被回收的**金枝**越来越多… |
| Nelly | 8 | Nelly. → **耐莉**。 |
| Sinners | 9 | The clock only works for us Sinners. → 钟表只会作用于**罪人**。 |

处理方式：带证据的**直接采信旧译**；没证据的（106 个，多是新人物/新地名）用一小题问一次豆包
（附灰机 wiki 检索与上下文），定译后**写回术语表**，之后就永久复用。
→ 这一步做完，第十章所有专有名词都是「零协既有译法」或「一次决策、全程一致」。

### L4 风格语料（已实现，58 842 对）
`data/translate/范例行对.jsonl`：每片提示词里附 5 条**同说话人优先**的英中行对，
让豆包对齐零协的语感（敬语 / 口癖 / 标点 / 省略号用法）。

## 3. 外包流程（豆包，老规矩）

```
build_glossary  →  export_translate_tasks（分片，自带提示词）
     →  send_translate_tasks（剪贴板 + 唤起豆包 + 选中文件 + 进度）
     →  豆包回包 JSON 存 data/translate/ans/<同名>.json
     →  import_translate_answers（校验 → 合并 → 中英对照 → 零协结构文件）
     →  pack_translation（可选：生成补丁文件，交付进游戏）
```

**分片规格**（`export_translate_tasks.py`）

- 粒度：按文件分段，**每片 ≤ 60 行**（实测豆包一次 60 行质量稳定；大文件如 `S1004B`（338 条）拆 6 片）
  → 第十章剧情预计 **30~35 片**。
- 每片内容：任务说明 + 输出 JSON schema + **本片说话人表** + **本片命中术语子表（含旧译证据）**
  + 5 条范例行对 + 逐行数据（行号｜说话人｜英文原文 + 前一行上下文）
- 输出 schema（与既有流水线一致，便于复用工具）：

```json
{"lines":[{"n":12,"zh":"……","note":"术语依据（可空）"}],
 "unknown":[{"term":"Grand Magasin Sisyphe","question":"新地名，建议译名？"}]}
```

**为什么坚持分片 + JSON 回包**：单次请求越短越稳；结构化回包才能做「术语一致性 / 漏行」机器校验，
而不是靠人肉通读。

## 4. 质量校验（`import_translate_answers.py` 的硬性门槛）

| 检查 | 规则 | 不通过 |
| --- | --- | --- |
| 行号完整 | 每片应回的行号集合 == 发出的集合 | 打回该片 |
| 术语一致 | 译文里术语必须与 `glossary.json` 完全一致（含全半角、标点） | 自动改写 + 记违规 |
| 说话人 | `teller` / `title` 用 L2 表；`???` → `？？？` | 自动改写 |
| 格式标签 | `<ruby=…>`、`<color=…>`、`<size=…>`、`[Keyword]`、`\n`、`{}` 占位符原样保留 | 打回 |
| 数字与符号 | 数字、百分号、破折号、省略号数量不得无故变化 | 打回 |
| 复用一致 | 与已译章节完全相同的英文行 → 直接采用零协译文（提示 + 自动填入） | 自动填入 |
| 长度 | 中文长度 ≤ 英文 × 1.2（气泡/UI 文本 ≤ × 0.8） | 标黄，人工看 |
| 抽检 | 每片随机 5 行人工复核 | — |

校验通过后产出：
- `data/translate/out/第十章-中英对照.md`（**交付物之一：双语对照**：说话人｜英文｜中文）
- `data/translate/out/第十章-中英对照.csv`（表格版，方便你在 Excel/表格里过一遍）
- `data/translate/out/zh/S1001B.json …`（零协结构的中文文件，供第 5 节交付）

## 5. 交付方式（三选，建议 a → b 分两步走）

**(a) 只留对照，不动游戏**（零风险，马上能看）
产出第 4 节的中英对照 md/csv；也可以把它作为「参考文本」放 `data/translate/out/`，
边看边在程序里手动改零协已译部分。

**(b) 生成补丁文件，让游戏里的第十章变成中文**（要一步程序扩展）
因为这 38 个文件零协包没有，需要：把 `out/zh/*.json` 作为「**补译文件**」放进副本包
`LLC_zh-CN_custom/`，并让部署器**保留**它们（现在 `deploy.py` 会把不在零协包里的文件
从副本包删掉 —— 这是需要新增的能力：**「补译/新增文件」白名单 + 校验**）。
风险与注意：
- 这些文件要跟游戏版本同步更新（零协更新后，同名词条应以零协译文为准，我们的译文退居补丁）；
- 交付前必须整体备份（程序已有「立即备份 / 备份管理」）；
- 建议先只上**剧情**，战斗文本（技能/状态描述）等零协更新后再取舍。

**(c) 等零协更新**：零协一旦发布第十章，直接用程序现有的「原文 ↔ 英文 ↔ 自定义」逐条改，
本方案的术语表与对照文档仍然有用（校验用）。

## 6. 脚本接口（待实现的三个，参数化便于复用）

| 脚本 | 作用 | 关键参数 |
| --- | --- | --- |
| `export_translate_tasks.py` | 生成分片任务包（自带提示词、术语子表、范例） | `--chapter 10`、`--part story\|battle`、`--per 60`、`--out data/translate/paste` |
| `send_translate_tasks.py` | 老规矩送片（剪贴板 + 豆包 + 进度，自动挑下一片） | `--status`、`--index N` |
| `import_translate_answers.py` | 校验 → 合并 → 出对照与零协结构文件 | `--strict`、`--out data/translate/out`、`--chapter 10` |
| `build_glossary.py` **（已实现）** | 术语表 / 说话人 / 新词候选 / 范例行对 | `--chapter 10`、`--zh`、`--en` |
| `pack_translation.py`（可选） | 把 `out/zh` 打进补译包并部署 | `--deploy <exe 目录>` |

换章节时：`--chapter 11` 重新跑这几个脚本即可；术语表会随零协更新自动变长，
新词候选会自动只列「第 11 章新出现的」。

## 7. 每章 Checklist（下次直接照做）

1. 确认新章节在英文基线里、零协里缺哪些（`python scripts/survey_ch10.py` 同类勘察）
2. `python scripts/build_glossary.py --chapter NN`（术语表 / 说话人 / 新词候选 / 范例）
3. 处理新词候选：带证据的直接采信；没证据的单独问一次豆包 → 写回术语表
4. `export_translate_tasks.py` 分片 → `send_translate_tasks.py` 逐片送豆包 → 回包存 `ans/`
5. `import_translate_answers.py` 校验合并 → 抽检 5 行/片
6. 出「中英对照」给对方/自己过一遍 →（可选）`pack_translation.py` 生成补丁
7. 全部产物进 git（`python scripts\git_snapshot.py "第十章翻译"`）
